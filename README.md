## Presk

Presk is a project that allows pedagogical animations to be described using a
declarative language, designed to be reliably generated by an AI rather than
hand-coded.

The goal is to make the creation of educational animations (grammar, physics,
mathematics lessons, etc.) as simple as describing the scene in natural
language to an AI, without having to tinker with SVG or low-level animation
code.

⚠️ Status: Project in the design phase. The language specification is still
under active iteration. This repository contains a working v1 skeleton of the
engine — enough to create objects, animate them, bind values between them and
render them with PixiJS — with clearly marked gaps where the spec goes further
than the current implementation (see "Known gaps" below).

## Project Structure

The project is composed of three distinct parts:

### `language/`
Defines the DSL (Domain Specific Language): the grammar, the JSON format, and
the full specification of the language used to describe an animation
(objects, properties, timing, expressions, anchoring, etc.). See
`language/spec.md`.

### `core/`
Contains the engine: the DSL compiler, the resolution of expressions and
dependencies, timeline management, and rendering. This is what executes a
file written in the language defined in `language/`. See `core/README.md`
for the internal architecture (this is where most of the code lives today).

### `lib/`
Not started yet. Will contain the pre-built component libraries, organized by
domain (for example: electrical circuits, French grammar, geometry...). These
components make it possible to describe a scene at a semantic level rather
than drawing each element by hand.

## Why This Project

Most existing tools used to generate pedagogical animations via AI (Manim,
imperative code, raw SVG) produce code that is difficult to validate and fix
reliably. Presk aims for the opposite: a strict, unambiguous format with
ready-to-use business components, allowing an AI to generate correct
animations repeatably.

## Getting started

```bash
pnpm install
pnpm --filter @presk/core dev      # opens the demo (renders core/src/compiler/mockInput.json)
pnpm --filter @presk/core test     # runs the unit tests
```

## Known gaps vs. the spec (`language/spec.md`)

This v1 focuses on getting the *architecture* right (see
`core/src/README.md` for the responsibility split) rather than implementing
every corner of the DSL. Not yet implemented, tracked as TODOs in the
relevant files:

- `group` / `ungroup` actions (§7).
- Path anchoring, `pathX`/`pathY`/`pathAngle` (§9).
- `boundingBox.*` prefix in expressions (§4.3) — only the direct corner
  points (`topLeft`, `center`, ...) are supported.
- Cycle detection in the dependency graph (§8.4-8.5) — a cyclic `follow`
  will currently just loop forever reading stale values instead of raising a
  compile-time error.

Everything else in the spec (create/set/transform/follow/unfollow/destroy,
timeline position parameters, named labels, expressions on scalar/point
props) is implemented.
